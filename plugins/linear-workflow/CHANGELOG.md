# Changelog

## 0.1.2 — 2026-10-05

- `issue-review` and `issue-ship` can be invoked by Claude itself, not only typed as slash commands
  (`disable-model-invocation` removed). When Claude invokes `issue-ship` without the user asking to
  ship, it confirms the issue and PR with the user before merging

## 0.1.1 — 2026-10-04

- Acceptance criteria written under sub-headings, or as prose, are now checked by `issue-review`
  (they were hidden from `issue-start` but missed by the parser)
- The plugin package includes its MIT `LICENSE`
- Release workflow: verifies the tagged commit (validate, type-check, tests) before publishing, and
  marks `-rc`-style versions as prereleases; CI pins Claude Code 2.1.289
- Removed the README screenshot

## 0.1.0 — 2026-10-04

First public release.

- Skills: `issue-next`, `issue-start`, `issue-review`, `issue-ship`, `issue-plan-cycle`
- CLI `bin/linear-workflow.mjs`: one call per skill step (`start`, `review`, `ship`) returning only
  what that step reads, plus `config`, `resolve`, `issue [--view]`, `queue`, `plan-cycle`, `transition`,
  `set-cycle`, `pr-check`, `pr-merged`; compact JSON, `--pretty`, `--out`. The skills' deterministic steps run here instead of through the LLM
- Agent: `linear-manager`, for issue creation and as the CLI's fallback
- Evals for the skills' guardrails (11 cases), run against canned CLI answers
  (`EVAL_LINEAR_WORKFLOW_FIXTURES`), with `evals/RESULTS.md` generated by `npm run eval`
- `issue-review` checks the acceptance criteria and refuses on another issue's branch; the skills
  name the destructive git commands they never run
- Project settings for state names, branching and the issue template; skills follow the project's
  own conventions (CLAUDE.md, CONTRIBUTING.md, PR template) first
- `lib/`: code shared by the CLI and the mod (Linear client, ranking, roll-up, PR verdicts)
- `issue-next` and `issue-plan-cycle` run on Haiku
- Mod: band and details pane for the current issue, `/linear` command, list of other sessions,
  conflict and scope-drift warnings, issue held when another session moves the shared branch
